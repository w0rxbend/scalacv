# Phase 8 — CI (assessment + gaps)

*The plan asks to "specify the jobs." Most already exist — and better than the plan's suggestion (RSS, not `maxBytes`). This documents what is present, then the genuine gaps.*

---

## Already present (and well-built)

| Plan requirement | Status in `ci.yml` |
|---|---|
| Multi-JDK matrix with correct platform classifiers | **Yes** — JDK 17/21/25 on ubuntu, per-rung `MILL_JVM_ID` (`ci.yml:19–45`), **plus a JDK-assertion gate** so the matrix isn't decorative (`:39–42`) |
| Multi-arch | **Partial** — macOS-14 **arm64** smoke + `core.test`/`zio.test` (`ci.yml:155–181`) |
| Leak suite | **Yes, and correctly RSS-based** — `leak-check` drives the pipeline 2000× in one JVM and gates on `/proc/self/status` **VmRSS delta** with a 200 MB ceiling (`ci.yml:62–139`). This matches Phase 6's finding that RSS, not `totalBytes`, is the only signal that sees a scalacv Mat leak. |
| Static-analysis gate | **Yes** — scalafmt `checkFormatAll` + scalafix `--check` over all published modules (`ci.yml:141–153`) |
| Forked-JVM crash detection | **Partial** — `-Xfatal-warnings` compile + the leak driver runs under `-Xmx256m` so an on-heap leak OOMs; native crashes surface as a dead worker → nonzero run |
| Headless-native smoke | **Yes** — ubuntu (no GTK) + macOS `@rpath` smoke (`ci.yml:51–60, 169–174`) |
| Publishing integrity | **Yes** — `publish-shape` (exact publishable set + `PublishedPomTest`) and `consumer-smoke` (from-clean-cache resolve + native load) (`ci.yml:183–253`) |

The `leak-check` comment references prior **"H1/M3/L2/L3 leaks"** — this codebase was audited and hardened before; the RSS gate is the residue of that work. That context matters: the ownership discipline observed in Phases 1–2 is *earned*, and the new findings here live on paths the existing single-pipeline gate does not exercise.

## Genuine gaps

1. **The leak gate exercises one path only.** `leak-check` drives `read→gray→canny→bytes` (`ci.yml:104–108`) — the common `Image` chain, which Phase 6 confirmed is flat. It would **not** catch **P2-1** (`blurBackground` receiver leak), **§3.2** (`Animation.gif` error path), the **§3.1** `withPolygons` residue, or the `Intrinsics.*` per-call allocation — those are different code paths. **Fix:** extend the leak driver (or add cases) to cover the finding-specific paths from [04-test-plan.md](./04-test-plan.md) §3a, each as an RSS-delta assertion.
2. **No coverage gate.** Scoverage is not wired (Phase 4 §1). **Fix:** add a coverage job with a ratcheting threshold once a measured baseline exists.
3. **No profiling-baseline artifact for trend comparison.** `leak-check` gates on an absolute delta but stores nothing. **Fix:** emit the RSS baseline/final/growth (already printed, `ci.yml:118–120`) as a job artifact / step-summary so trends are visible across runs, per the plan's "profiling baseline stored as an artifact."
4. **Windows absent — documented and defensible.** The `./mill` bootstrap is Unix-only and Mill 1.1.7 ships no Windows launcher (`ci.yml:158–165`), so a `windows-latest` leg would fail at the launcher without testing the loader. The Windows loader path (bulk-load fallback, `OpenCv.scala:120–146`) is therefore **implemented but unverified in CI**. **Fix:** revisit when a working Windows Mill invocation exists; until then, note the Windows loader as tested-by-construction-only in the README/limitations.
5. **No dedicated forked-per-suite crash module.** `DoubleFreeTest` and the ownership tests share the core JVM (Phase 0). A regression that segfaults takes the whole worker down (still a nonzero run — acceptable), but per-test attribution is lost. **Fix (optional):** a small `crash`/`leak` test module with `testForkGrouping` per suite so a use-after-close regression names the offending test.

## Proposed job set (delta over current)

Keep every existing job. Add:

- **`coverage`** (ubuntu): `mill __.scoverage.xmlReport` + threshold gate (after baseline).
- **`leak-check` extension**: add the finding-specific RSS-delta cases; publish the RSS numbers as a step-summary artifact.
- **(optional) `crash`** (ubuntu, forked-per-suite): the use-after-close / double-free suite in JVM isolation.
- **(deferred) `windows`**: once Mill runs on Windows, a loader smoke leg.

Nothing here changes the matrix's core shape — the JDK matrix, RSS leak gate, arm64 leg, and publishing gates are already the right spine.
